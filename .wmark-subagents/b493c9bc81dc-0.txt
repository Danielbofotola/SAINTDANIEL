## 4. Élève ↔ inscriptions des années passées + archives

- **`app/Models/Eleve.php`** : relation **non filtrée** par année —
```php
public function inscriptions(){ return $this->hasMany(Inscription::class); }
```
Chaque `Inscription` porte `annee_scolaire_id` → `inscription->anneeScolaire->libelle`.
- **Preuve de l'usage « toutes années »** : `PrefectureDashboardController::eleveFiche()` fait `$eleve->load(['…','inscriptions.classe'])` **sans `anneeEnCours()`**, et `resources/views/prefecture/eleve-fiche.blade.php` boucle `@foreach ($eleve->inscriptions as $inscription)` → colonnes *Année scolaire / Classe / Cycle / Date d'inscription / Statut*. C'est le dossier élève historique complet.
- À l'inverse, les listes/e effectifs limitent à l'année : `Eleve::scopeInscritAnneeEnCours()` et `->inscriptions()->anneeEnCours()` (scope du trait `BelongsToAnneeScolaire`, qui force `where('annee_scolaire_id', enCours()->id)` ou `whereRaw('1 = 0')`).
- **Pas de table archive par élève.** `archives_annees` (`app/Models/ArchiveAnnee.php`) ne stocke qu'une **synthèse financière globale par année** (`total_eleves_inscrits, total_recettes, total_attendus, total_impayes, solde_final…`) — aucun détail par élève. L'historique individuel repose entièrement sur les lignes `inscriptions` (et leurs `bulletins`/`paiements`/`deliberations`), qui restent en base pour les années clôturées (consultables dès qu'on ne filtre pas par `anneeEnCours`).

Point d'attention : `DeliberationController` génère l'inscription de l'année suivante ; le parcours pluriannuel d'un élève se reconstruit en enchaînant ses `inscriptions` par `annee_scolaire_id` + `Deliberation` (décision/classe suivante).
